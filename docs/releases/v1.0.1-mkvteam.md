# StudentOS v1.0.1-mkvteam

## Release Purpose

`v1.0.1-mkvteam` is the StudentOS security and delivery hardening patch for the MKV Team. It preserves the current student-platform capabilities while improving the safety, transparency, and repeatability of the container build and release process.

## What Changed

| Area | Patch release change |
| --- | --- |
| Container runtime | Tomcat now runs as a dedicated non-root account. Startup uses a restrictive file-creation mask and validates the configured HTTP port range. |
| Image boundary | The strict Docker build allowlist continues to exclude local configuration, private artifacts, archives, and environment files. |
| Release workflow | Publishing is limited to published GitHub Releases, and all external workflow actions are pinned to immutable commit references. |
| Build transparency | The published image includes provenance metadata and a software bill of materials. |
| Pre-release verification | Main-branch and pull-request changes run a no-publish container build plus CodeQL analysis for Java and GitHub Actions configuration. |
| Dependency monitoring | Dependency graph, Dependabot alerts, automated security fixes, and scheduled dependency review are active. |
| PostgreSQL driver | The PostgreSQL JDBC dependency was updated to the supported patched `42.7.13` release. |

## Verification Summary

The source passed Maven tests and WAR packaging after the dependency update. GitHub Actions completed the hardened no-publish container build and CodeQL analysis successfully. The PostgreSQL JDBC Dependabot alert identified during hardening is marked fixed.

## Run the Container Locally

After GitHub Container Registry publishing completes, pull the tagged image:

```bash
docker pull ghcr.io/lankuzumk/student-os:v1.0.1-mkvteam
```

Run it only with a database and local environment configuration you control:

```bash
docker run --rm -p 8080:8080 \
  --env-file .env \
  ghcr.io/lankuzumk/student-os:v1.0.1-mkvteam
```

Never put a production database URL, hosting secret, administrator credential, password, reset code, or production user data into a local environment file or container run command.

## Scope Note

This patch improves security controls and release evidence. StudentOS remains a university-project and controlled-pilot foundation; independent real-device and two-user testing remain appropriate before broader rollout.
